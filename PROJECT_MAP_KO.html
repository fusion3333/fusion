외국인이 왜 한국을 선택하고, 어디서 막히며, 무엇을 고치면 실제 매출과 지역가치가 생기는지를 찾는 엔진

핵심은 관광객 수를 세는 것이 아니라 수요가 생기는 이유 → 선택 → 검색 → 예약·결제 → 이동 → 체류·활동 → 지출 → 만족·불만 → 다음 사람에게 확산을 한국의 실제 공급과 연결하는 것입니다.

왜 이렇게 만들었나?
관광공사·정부·카드·통신·검색·플랫폼·SNS·현장 자료는 각각 현실의 한 조각만 봅니다. 한 자료를 전체 진실로 쓰면 왜곡됩니다. 그래서 여러 센서를 단계별로 연결하고, 서로 같은 뜻이 아닌 값은 강제로 분리하도록 설계했습니다.

1. GitHub 자료가 흘러가는 과정

00 시스템 — 설계도

목적: 무엇을 어떤 기준으로 조사하고 연결할지 정합니다.

왜: 자료가 많아질수록 정의와 규칙이 없으면 서로 다른 숫자를 잘못 합치기 때문입니다.

들어오는 근거: 우리 통합설계, 관광공사·OECD 등 공식 방법론, 경쟁기업 방식, 학술 측정법.

01 원본 근거 — 증거창고

목적: 주장보다 먼저 원문·통계·공식자료를 보존합니다.

왜: 나중에 모든 판단을 원출처까지 역추적하기 위해서입니다.

대표 출처: 한국관광공사, 문체부, 법무부, 통계청·KOSIS, 지자체, 교통기관, 각국 정부, 기업 공식자료, 논문.

02 관측 — 증거에서 사실 추출

목적: 원자료에서 비교 가능한 사실만 뽑습니다.

왜: 문서 한 개의 해석과 실제 측정값을 섞지 않기 위해서입니다.

입력: 01의 검증된 근거. 출력: 국가·월·지역·행동단계별 관측.

03 연결망 — 관계를 잇기

목적: 관광객·욕구·지역·상품·플랫폼·교통·결제·돈·실패를 연결합니다.

왜: 사업기회는 단일 숫자보다 '연결이 끊긴 곳'에서 생기기 때문입니다.

입력: 02의 관측값과 정의된 관계.

04 데이터 — 실제 숫자 적재

목적: 10년×12개월, 국가×지역×업종 등으로 실제 데이터를 쌓습니다.

왜: 계절성·추세·충격·국가별 차이를 느낌이 아니라 숫자로 보기 위해서입니다.

출처: 국내외 공식 원자료, 기업·플랫폼 관측, 향후 현장·자체계측.

진단 → 사업기회 → 학습

목적: 병목과 숨은 수요를 찾고, 고칠 가치가 있는 것만 사업후보로 올립니다.

왜: 불편이 있다고 모두 돈 되는 사업은 아니기 때문입니다.

필요: 수요크기 + 실패분모 + 해결가능성 + 비용 + 실제 상승효과 + 불확실성.

3. 25축 위에 겹쳐 보는 8개 교차계층

① 목적지 후보·선택

한국을 안다 ≠ 후보에 넣는다 ≠ 선택한다. 일본 방문도 자동으로 한국의 손실로 보지 않습니다.

소스: 잠재방한조사, 선택연구, 경쟁국 자료, 향후 개인별 선택행동.

② 동행집단 의사결정

여행자·기획자·검색자·영향자·결제자가 서로 다를 수 있습니다.

소스: 동행유형 공식조사, 가족·집단 의사결정 연구, 향후 구성원별 조사.

③ 예산·지불의사·가격반응

실제로 쓴 돈과 원래 쓸 수 있던 돈, 얼마까지 낼 의향이 있는지를 분리합니다.

소스: 지출조사, 가격·선택 연구, 실제 노출가격·거절·할인 행동자료.

④ 수용량·재고·시간

등록 공급과 특정 시간에 실제 예약 가능한 공급은 다릅니다.

소스: 숙박·사업체 공식통계, 공급자·OTA 재고, 운영시간, 언어·인력.

⑤ 사회적 확산

한 사람의 경험이 리뷰·영상·추천을 통해 다음 사람의 수요를 만들 수 있습니다.

소스: 관광데이터랩 SNS, 플랫폼 지표, 리뷰, 향후 노출→검색→예약 연결자료.

⑥ 미실현수요

한국에 오지 않은 사람, 예약을 포기한 사람, 경쟁국으로 바꾼 사람까지 봅니다.

소스: 후보집합·실패여정·경쟁국·예산·향후 대체행동.

⑦ 개입비용·인과효과

문제를 발견하는 데서 끝내지 않고, 고치면 실제 얼마나 늘고 비용은 얼마인지 봅니다.

소스: 시범사업, 비교집단, 정책평가, 실험·준실험, 실제 비용.

⑧ 불확실성

숫자가 틀릴 수 있는 이유를 표본·측정·편향·결측·시간·모형·인과 문제로 나눕니다.

소스: 각 원자료의 방법론·오차정보, 센서간 비교, 민감도검사.

4. 출처는 왜 여러 종류를 쓰는가?

하나의 출처가 모든 질문에 가장 좋은 것은 아닙니다. 입국자 수는 정부통계가 강하고, 실제 결제 실패는 결제·플랫폼 로그가 강하며, 숨은 불편은 후기와 현장이 더 잘 보일 수 있습니다.

출처층무엇에 강한가사용 원칙
정부·공공기관 공식자료입국, 인구, 사업체, 교통, 정책, 장기통계기본 골격과 기준값. 정의·개편·시계열 단절 확인.
출발국 정부자료그 나라 국민의 전체 해외여행과 목적지 분포한국에서 본 숫자를 출발국 관점으로 거울처럼 검증.
기업 공식자료예약, 결제, 재고, 수수료, 플랫폼 작동방식기업이 공식 공개한 범위까지만 사실로 사용.
검색·지도·SNS·후기관심, 언어, 불편, 유행, 발견과 확산절대 관광객 수로 오인하지 않고 추세·행동신호로 사용.
학술연구심리, 선택, 가격반응, 인과추론 방법우리 데이터의 빈칸을 숫자로 꾸미는 데 쓰지 않고 측정·해석 방법에 활용.
현장조사판매의사, 언어대응, 실제 운영, 숨은 공급·실패공개자료가 현실과 맞는지 직접 확인.
자체 행동·거래계측실제 시도분모와 전환·실패·거래 결과향후 최종 공식 학습의 핵심 결과자료.

5. 결국 무엇을 만들어내는가?

예: “미국 30~40대 가족이 한국 전통체험을 검색하고 좋아하지만, 특정 지역은 영어 예약·해외카드·마지막 10km 이동·주말 재고가 부족해 실제 방문으로 이어지지 않는다.”

엔진은 여기서 끝나지 않습니다. 얼마의 수요가 있었는가 → 몇 명이 어디서 포기했는가 → 실제 공급은 몇 자리인가 → 누가 결정하고 돈을 내는가 → 일본 등 대체지는 무엇인가 → 문제를 고치면 추가 예약이 얼마나 생길 가능성이 있는가 → 해결비용과 지역에 남는 돈은 얼마인가 → 이 추정이 얼마나 불확실한가까지 이어지는 것이 목표입니다.

즉 최종 상품은 '관광 통계 화면'이 아니라 기업·지자체·투자자가 어디에 무엇을 고치고 투자할지 결정하게 해주는 B2B 의사결정 정보입니다.

7. 절대 헷갈리면 안 되는 것

공급이 있다고 실제로 살 수 있는 것은 아니다

등록 객실 수 ≠ 오늘 예약 가능 객실 수. 영업 중 ≠ 원하는 시간 이용 가능. 플랫폼 잔여석 ≠ 우리 일행이 예약 가능. 화면상 가능 ≠ 실시간 확정 가능.

관심이 실제 여행은 아니다

조회 ≠ 관심 ≠ 검색 ≠ 한국을 후보에 넣음 ≠ 선택 ≠ 예약 ≠ 실제 방문.

돈을 썼다고 더 낼 의향이 있었다는 뜻은 아니다

실제 지출 ≠ 여행 전 예산 ≠ 최대 지불의사.

문제가 있다고 사업기회인 것은 아니다

병목을 고칠 수 있는지, 비용보다 효과가 큰지, 실제 전환을 올리는지 검증해야 합니다.

숫자는 항상 오차를 가진다

표본오차·측정오차·출처편향·결측·정의차이·시간노후화·모형차이·인과불확실성을 숨기지 않습니다.

이 지도의 역할

이 파일은 방대한 저장소를 처음 보는 사람도 프로젝트의 목적→자료→분석→진단→사업기회 흐름을 한 번에 이해하도록 만든 안내판입니다. 상세 근거는 각 시스템·근거·관측·데이터 파일에서 확인하고, 이 지도 자체를 새로운 원자료로 취급하지 않습니다.
