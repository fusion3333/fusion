# 대한민국 관광 데이터 소스 수집 맵 V1

기준일: 2026-08-27

## 목적
대한민국 인바운드 관광 Digital Twin 구축을 위해 공식기관·지역 관광기관·기업·OTA·플랫폼·커뮤니티에서 확보 가능한 데이터를 `합법적/공개적 접근 수준`별로 분류하고, L0→L7 적층에 사용할 Source Backbone을 정의한다.

## 접근 등급
- A1 OFFICIAL API: 공식 OpenAPI. 자동 수집 최우선.
- A2 OFFICIAL FILE: 공식 CSV/XLSX/ZIP/보고서. 정기 다운로드/정규화.
- A3 OFFICIAL WEB: 공식 통계/대시보드. 공개 다운로드 또는 허용 범위 내 수집.
- B1 PUBLIC PLATFORM DATA: 공개 상품·가격·평점·리뷰·정책 페이지. 플랫폼 약관/robots/접근제한 준수.
- B2 PARTNER/API: 제휴·공식 Partner API가 필요한 데이터. 승인 후 수집.
- C VOC/SOCIAL: 공개 리뷰·게시물·커뮤니티. 표본편향·약관·저작권을 별도 기록.
- X PRIVATE/PROTECTED: 로그인 뒤 비공개 데이터, 내부 예약량, 개인식별정보, 우회가 필요한 차단 데이터. 무단 수집하지 않음.

## 2. 지역 관광기관/지자체
모든 광역·기초 관광기관을 Source Registry에 등록한다.
우선순위:
- 서울관광재단/서울시
- 경기관광공사/경기도
- 인천관광공사/인천시
- 부산관광공사/부산시
- 제주관광공사/제주도
- 경북문화관광공사/경북·경주
- 강원관광재단/강원도
- 전북특별자치도문화관광재단/전주·전북
- 전남관광재단/광주·전남
- 대구문화예술진흥원 관광본부/대구
- 대전관광공사/대전
- 울산문화관광재단/울산
- 충남/충북 관광 관련 재단·지자체
- 세종 및 각 시군구 관광부서

지역별로 다음 데이터 유무를 조사한다.
`입도/방문자`, `국적`, `지역별 소비`, `카드`, `통신`, `내비`, `숙박`, `관광지`, `축제`, `체험`, `설문`, `만족/불만`, `MICE`, `의료`, `크루즈`, `항공`, `지역상품`, `인허가`, `다국어 콘텐츠`.

## 3. 기업/플랫폼
### 숙박/OTA
Booking.com, Agoda, Trip.com, Airbnb, Expedia, Hotels.com 및 국가별 주요 OTA.
수집 후보: 공개가격, 객실/상품명, 평점, 리뷰수, 공개리뷰, 위치, 시설, 취소정책, 언어, 세금/수수료 표시, 판매 가능 여부.
내부 예약량·전환율·비공개 재고·비공개 API는 공개 데이터로 간주하지 않는다.

### Experiences/Activities
Klook, KKday, Trazy, GetYourGuide, Viator.
수집 후보: 상품명, 카테고리, 지역, 가격, 할인, 리뷰수/평점, 예약수 proxy가 공개된 경우, 소요시간, 언어, 취소정책, meeting point, inclusions/exclusions, 공급자/브랜드 노출 여부.

### 지도/검색/리뷰
Google Maps/Travel, Naver Map, Kakao Map 등.
공식 API 또는 공개 접근 범위 우선. 대량 리뷰 수집은 서비스 정책에 따라 별도 승인/방법 검토.

### 결제/환전/통신/교통
카드사·간편결제·PG·환전/핀테크·eSIM/SIM·택시/모빌리티·철도/버스/항공 사업자의 공개 상품/요금/정책/공식 API/공공데이터.

## 4. 기사/학술/시장보고서
- 언론기사: 사건/트렌드/기업전략 탐색용. 사실은 가능하면 원 공식자료로 역추적.
- 증권사/컨설팅/기업 IR: 시장규모·기업 전략·수익구조 보완.
- 학술논문/연구보고서: 인과/행동/만족도/지역효과 가설 보강.

## 5. VOC/Social
Reddit, Threads, Instagram, YouTube, TikTok, 여행 포럼 및 국가별 커뮤니티.
목적: Needs/Wants/Pain/Delight/정보탐색/여행준비/현장불편 taxonomy.
주의: 국가·연령·플랫폼 편향을 기록하고 공식 설문과 교차검증한다.

## 6. 데이터 수집 원칙
1. 공식 API > 공식 파일 > 공식 웹 > 공식 Partner API > 공개 플랫폼 > VOC 순으로 신뢰 우선순위를 둔다.
2. 공개라고 해서 무제한 크롤링 가능한 것은 아니다. 약관·robots·API 정책·저작권·개인정보 규칙을 기록한다.
3. 우회 로그인, CAPTCHA 회피, 비공개 endpoint 악용, 개인식별정보 수집은 하지 않는다.
4. 플랫폼 데이터는 snapshot date, 검색조건, 통화, 세금 포함 여부, 지역, 인원, 숙박일 등 query context를 반드시 저장한다.
5. 가격과 재고는 실시간성이 높으므로 historical snapshot으로 저장한다.
6. 리뷰 원문은 필요한 범위에서만 보관하며, 분석 DB에는 sentiment/topic/issue 등 파생 feature 중심으로 저장한다.

## 9. 목표
'모든 데이터를 긁는다'가 아니라, 접근 가능한 공식/공개 데이터를 최대 범위에서 수집하고 접근 불가 영역도 데이터 공백 자체로 기록해 정보비대칭과 사업기회를 찾는다.
